Submission Instructions

Benchmark Submissions (All Tracks)

Please follow the instructions given in the call for benchmarks, and submit benchmarks by email to maxsatevaluation@gmail.com using the subject title "MSE26 benchmark submission" by the submission deadline specified on the left-hand side of each page.

Solver Submissions: Main Tracks (Exact and Anytime)

Note: Even if the exact tracks will be not be run StarExec, participating solvers should still be submitted following a procedure which is very similar to the previous submission of solvers onto StarExec. Essentially, the procedure is mostly identical to previous years expect for the fact that the zipped solver should be submitted by email to maxsatevaluation@gmail.com with the subject title "MSE26 solver submission". Please specify the track(s) in which your solver participate in the e-mail.

New for 2026: The main tracks of the evaluation are Exact-W(eighted), Exact-U(n)W(eighted), Anytime-W, and Anytime-UW. Specifically, every solver in the anytime track will be evaluated under all timeouts. Such solvers will be given the timeout as the second comand line parameter. Another difference to earlier years is that only one zip file should be submitted, regardless of the number of tracks in which a solver partcipates. Participoation in different tracks should instead be handled by different configuration (run) scripts.

Solvers need to be submitted by the submission deadline (specified on the left-hand-side of the page). To submit a solver you will need to prepare a zip or tar file (the suffix needs to be .zip, .tar, tar.gz, or .tgz) with the following file and directory structure 

./bin/<your_solver_binary>
./bin/run_TRACK
./code/<your_source_tree>
./doc/<your_solver_description>.pdf

  • ./bin/solver_binary is your executable which should be a statically linked linux executable.
  • ./bin/run_TRACK is one or more track specific configuration. It is just a shell script used to invoke your solver in the corresponding track. A bare bones version would be 

    #!/bin/bash
./<your_solver_binary> $1

    which will invoke your solver on an input file passed into the script as the $1 variable. More elaborate versions might supply various parameter settings to your solver. TRACK should be one of:
    • EXACT-W for solvers participating in the exact weighted track
    • EXACT-UW for solvers participating in the exact unweighted track
    • ANYTIME-W for solvers participating in the anytime weighted track
    • ANYTIME-UW for solvers participating in the anytime unweighted track

  • Remember that, in contrast to previous years, anytime solvers are expected to be run under all three different timeouts speficied on the tracks page and can not participate only under some of them. The timeout in seconds will be given as the second parameter to the solvers. An example of a barebones runscript for an anytime solver that reads the timeout would be: 

    #!/bin/bash
./<your_solver_binary> $1 $2

  • ./code/ is where you place your source code (which can be in a directory tree).
  • ./doc/ is where you place your PDF formatted description of your solver.

Update: To allow for solvers written in Python, an extra script ./bin/build_solver is allowed. In this case, Python (version 3.13.1) and virtualenv (version 20.29.2) are installed and the build-script creates a virtual environment (in the bin-folder), installs all the requirements and builds the solver. The script run_TRACK then loads this virtual environment and calls the solver on the given instance similar as the C++ solvers.

Testing Your Solver Prior to Submissison

The organizers strongly urge developers to test their solvers prior to submitting them. As of 2024, a solver in the main tracks needs to pass a regression suite of small instances which caused at least one solver from the last evaluation to crash.

Further testing of solvers can be done with the verify_soln tool. When invoked on a WCNF instance and a solver output, the tool will check that the (i) all hard clauses are satisfied, (ii) the solution provided in the 'v' line matches the value of the last 'o' line. Later in the spring, we will also publish a more extensive fuzzer for testing solvers. Details on the fuzzer will be anounced later.

Solver Submissions: Incremental Track

To submit a solver to the incremental track, implement a subset of functions defined in the IPAMIR header file as described in the comments of the header file. If your solver does not provide support for a particular function, the solver state must be changed to ERROR. Place your solver into a directory named after the solver. Issuing make in this directory must result in a successful build of the solver as a static library. Please see the maxsat/solver2023 directory in the IPAMIR repository for an example (non-incremental) solver. Submit your solver as a single zip or gzipped tar package via email to maxsatevaluation@gmail.com using the subject title "MSE26 incremental solver submission" by the submission deadline detailed on the left-hand-side of each page.
